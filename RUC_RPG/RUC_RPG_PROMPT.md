# 러크 RPG (가칭 "Ruc Chronicle") 베타 — Claude Code 개발 지시서

> 이 문서는 러크 마인크래프트 서버에 나중에 도입할 RPG 체제를 **러크 웹사이트(https://ruc-server.vercel.app)에서 2D 픽셀 웹게임으로 먼저 구현해 베타테스트**하기 위한 개발 명세다.
> 문서 전체를 끝까지 읽은 뒤 **§0의 작업 원칙**과 **§30의 개발 단계**에 따라 진행한다.

## 표기 규칙
| 태그 | 의미 |
|---|---|
| **[원문]** | 기획자가 직접 정한 요구사항. 임의로 바꾸지 않는다. |
| **[추가]** | 게임 완성도를 위해 보완한 설계. 합리적인 근거가 있으면 조정할 수 있으나, 바꾸면 `docs/DECISIONS.md`에 기록한다. |
| **[해석]** | 원문에 모순·오타·모호함이 있어 해석한 부분. 원문 의도와 해석 근거는 §31에 정리했다. |
| 수치 | 모든 수치는 **초기 밸런스 값**이다. 코드에 하드코딩하지 말고 데이터 파일(§26)에서 불러온다. |

## 0. Claude Code 작업 원칙 [추가]

1. **먼저 탐색한다.** 코드를 쓰기 전에 기존 저장소를 분석하고 `docs/RPG_RECON.md`에 아래 내용을 정리한다.
   - 사용 중인 프레임워크(Next.js / 정적 HTML 등), 라우팅 구조, 빌드·배포 방식(로컬 → git push → Vercel)
   - 기존 **디스코드 로그인 구현 방식**(NextAuth, 자체 OAuth 등)과 세션 저장 위치
   - 기존 DB(있다면)와 **RUC 잔액·우편함** 데이터가 어디에 있는지(MC 플러그인 DB, 디스코드 봇 MOOKI DB 등), 디스코드 ID ↔ MC UUID 매핑 여부
   - `/home` 페이지 구조와 디자인 시스템(폰트·색상·버튼 스타일)
2. **기존 사이트를 깨뜨리지 않는다.** RPG 관련 코드는 `/rpg` 라우트와 별도 디렉터리(예: `apps/rpg-client`, `apps/rpg-server`, `packages/rpg-shared`)에 격리한다.
3. **데이터 주도 설계.** 스킬·아이템·몹·직업·버프·속성·퀘스트·상점·던전 정의는 모두 JSON/TS 데이터 파일로 분리한다. 밸런스를 바꿀 때 로직 코드를 건드리지 않아도 되게 한다.
4. **서버 권위(Server-authoritative).** 데미지, 드롭, 강화 확률, RUC 증감, 아이템 이동은 전부 서버에서 판정한다. 클라이언트는 입력과 표시만 담당한다.
5. **단계별 완료.** §30 단계를 순서대로 진행하고, 각 단계가 끝날 때마다 로컬에서 실행할 수 있는 상태로 만들어 커밋한다. 단계별 완료 기준(DoD)을 충족했는지 스스로 점검한다.
6. **멈춰서 질문할 때.** 기존 RUC/우편함 DB 구조가 이 문서와 충돌하거나, 실제 재화에 영향을 주는 작업(§17-1)일 때는 진행 전에 사용자에게 확인한다. 그 밖의 모호함은 [추가] 원칙으로 판단하고 `DECISIONS.md`에 기록한다.
7. **비밀값.** 토큰·키는 `.env`에만 두고 커밋하지 않는다. `.env.example`을 제공한다.
8. **언어.** 게임 내 텍스트는 한국어. 문자열은 `locales/ko.json`에 모아 둔다. 조사 처리(이/가, 을/를)는 유틸 함수로 만든다.

| 항목 | 내용 |

## 2. 기술 아키텍처 [추가 — 원문 '환경 구축' 구체화]

### 2-1. 구성
```
[브라우저]
  ├─ /rpg 페이지 (기존 사이트 프레임워크)
  │   ├─ 게임 렌더러: TypeScript + PixiJS v8 (WebGL, 실패 시 Canvas 폴백)
  │   └─ UI 오버레이: DOM/CSS (기존 사이트가 React면 React) — 인벤토리, 상점, 설정 등 팝업
  │
  ├─ HTTPS → Vercel API Route: /api/rpg/ticket
  │       디스코드 세션 확인 → 단기(60초) 서명 JWT "게임 입장 티켓" 발급
  │
  └─ WSS  → 게임 서버 (상시 실행되는 Node.js 프로세스, Vercel 외부)
          Node.js + TypeScript + Colyseus(또는 uWebSockets.js 직접 구현)
          ├─ 방(Room) 단위: 광장 채널, 필드 채널, 던전 인스턴스
          └─ DB: PostgreSQL (기존 DB가 있으면 거기에 rpg_ 접두 테이블)
```
- **Vercel은 서버리스라서 상시 WebSocket 게임 서버를 띄울 수 없다.** 게임 서버는 별도 호스트에서 돌린다. 베타 단계에서는 운영자 로컬 PC + 터널(Cloudflare Tunnel 등)이나 서울 리전 VPS를 권장한다. 핑을 줄이려면 한국 리전이 필수다.
- 게임 서버 주소는 환경변수 `NEXT_PUBLIC_RPG_WS_URL`(또는 프레임워크에 맞는 이름)로 주입한다.
- 공유 타입·데이터·공식은 `packages/rpg-shared`에 두고 클라이언트와 서버가 함께 쓴다(데미지 공식 미리보기, 툴팁 계산 등).

### 2-2. 넷코드
| 항목 | 값 |
|---|---|
| 서버 틱 | 20Hz (50ms). 상태 스냅샷은 델타 전송 |
| 클라이언트 렌더 | 설정한 FPS 제한(§24)까지 requestAnimationFrame |
| 내 캐릭터 이동 | **클라이언트 예측 + 서버 보정(reconciliation)**. 입력마다 시퀀스 번호 부여 |
| 타 엔티티 | 100ms 버퍼 **보간(interpolation)** |
| 스킬 | 클라이언트는 `{skillSlot, aimAngle, targetId?, seq}`를 보낸다. 시전 모션·이펙트는 즉시 낙관적으로 재생하고, 서버가 쿨다운·자원·사거리를 검증한 뒤 판정 결과를 브로드캐스트한다. 거부되면 이펙트를 취소하고 자원 UI를 롤백한다 |
| 투사체·범위 판정 | 서버에서 수행. 지연 보상(최대 150ms 되감기) |
| 핑 표시 | 2초마다 ping/pong RTT 측정, 최근 5회 평균 |
| 채널 | 방당 최대 인원(광장 60, 필드 40) 초과 시 자동으로 채널 분리. 채널 이동 UI 제공 |
| 직렬화 | 바이너리(Colyseus schema 또는 MessagePack). 위치는 정수 px 단위 |

### 2-3. 인증 흐름
1. `/home` 버튼 클릭 → `/rpg`
2. 디스코드 세션이 없으면 "디스코드로 로그인" 화면 → 기존 OAuth 흐름 재사용 → 로그인 후 `/rpg`로 복귀
3. `/api/rpg/ticket`에서 `{discordId, username, avatar, exp:60s}` JWT 발급 (`RPG_TICKET_SECRET`)
4. 게임 서버 접속 시 티켓 검증. 같은 계정이 중복 접속하면 기존 연결을 끊는다
5. 최초 접속 시 캐릭터 생성 화면(§8-1)

## 3. 세계관 [원문 + 추가]

| 항목 | 내용 |
|---|---|
| 분위기 | **밝음** [원문]. 따뜻한 채도, 유머러스한 NPC 대사, 잔혹 묘사 없음 |
| 시대 | **마법·정령 등 신기한 것들이 존재하는 중세 유럽** [원문] |
| 세력 구조 | **파티 → 길드 → 영지 → 국가** [원문]. 베타에서는 **파티만 구현**하고, 길드·영지·국가는 DB 스키마와 UI 자리만 마련한다 |

**[추가] 배경 설정 초안**
- 대륙 이름: **루크리아(Rucria)**. 열두 정령(= 12속성, §12)이 세계의 균형을 지킨다.
- 시작 도시: **햇살광장 "솔라스"**. 모든 모험가가 처음 도착하는 자유 도시이며 어느 국가에도 속하지 않는다(안전지대).
- 메인 갈등: 고대 유적에서 "균형이 깨진 정령"이 깨어나 몬스터가 늘어난다. 모험가는 파티를 맺고 유적(던전)을 정화한다.
- 정령 신앙: 플레이어는 캐릭터 생성 때 한 정령의 가호(= 주 속성)를 받는다.

## 4. 핵심 게임 루프 [추가]
```
광장(퀘스트 수락·상점·강화·우편 수령) → 필드 사냥(경험치·재료)
   → 파티 결성 → 던전 스테이지 도전(희귀 드롭·RUC)
   → 광장 복귀(강화·마법부여·거래·전직) → 더 높은 스테이지
```
- 세션 1회 목표 플레이 시간은 20~40분. 던전 1회 도전은 10~25분.
- 사망 페널티(§13-4)는 가볍게 해서 밝은 분위기에 맞춘다.

### 6-3. 스탯 공식 [추가]
- **방어 상쇄**: `받는피해 = 원피해 × 100 / (100 + max(0, 방어력 × (1 − 관통%)))` (방어력 100이면 50% 경감, 수확체감)
- **속성 방어**: `× 100 / (100 + 속성방어력)`을 추가로 곱한다
- **공격 속도**: `시전시간 = 기본시전시간 × 100 / 공격속도`. 공격속도 상한 250
- **이동 속도**: 100 = 초당 64px(= 4타일). 달리기 ×1.6. 상한 200
- **스태미나**
  - 달리기 초당 12, 구르기 1회 20, 평타 1회 3, 스킬은 스킬별(§10-3)
  - 실제 소모 = `기본소모 × 100 / (100 + 지구력)`
  - 1.5초 동안 소모가 없으면 초당 최대치의 15% 회복
  - 0이 되면 **[탈진]**: 달리기·구르기 불가, 이속 −30%, 최대 HP의 0.5%씩 매초 감소(최소 HP 1까지 — 탈진만으로는 죽지 않음 [추가]). 스태미나가 20%까지 차면 해제 [원문 "체력 지속 소량 감소" 구체화]
- **재생력**: 비전투 상태(5초간 피해 주고받음 없음)에서 초당 `재생력 × 0.4` HP 회복, 전투 중에는 그 25%
- **마나/기력 회복**: 초당 최대치의 1.5% (비전투 3%)
- **정신력**: 받는 힐·주는 힐 `× (1 + 정신력/200)`. 디버프 저항 확률 `정신력/(정신력+200)`(정신계 디버프에 적용, §11-2)
- **운**: 드롭 개수 보너스 `+운/200` 기대값(소수점은 확률), 희귀도 상향 롤 `+운 × 0.05%p`. 상한 운 200

## 10. 스킬

### 10-1. 슬롯과 키 [원문 + 해석]
- 학습한 스킬 중 **4개를 기본 슬롯에 장착** [원문]. 슬롯 변경은 비전투 상태에서 K 창으로
- 기본 키: **Q / C(=W 슬롯) / E / R·X** [해석, §5]. 이후 추가되는 슬롯(Lv20·Lv40에 1칸씩 [추가])의 키는 사용자가 지정 [원문]
- **슬롯 규칙** [원문]

| 슬롯 | 역할 | 쿨타임 | 자원 소모 |
|---|---|---|---|
| **패시브** | 직업의 전형적 특성. 대부분 상시 발동. 너무 강하면 너프하거나 내부 쿨타임 추가 | — / 내부 쿨 | — |
| **Q** | 평타처럼 주력으로 부담 없이 쓰는 스킬 | **가장 짧음** (1~4초) | **가장 적음** |
| **W(C키)** | 호신·도주·회피 스킬 | **궁극기 다음으로 김** (12~20초) | 중간 |
| **E** | Q보다 강력 | Q보다 김 (6~10초) | Q보다 많음 |
| **R/X 궁극기** | 직업의 가장 영향력 크고 강력한 스킬 | **가장 김** (60~120초) | **극심** |

- 각 슬롯에 넣을 수 있는 스킬이 **슬롯별로 여러 개** [원문]. **[추가] 최소 기준**: 세부 직업 1개당 Q 3개, W 2개, E 3개, R 2개 (계열 공통 스킬 + 세부 직업 전용 스킬 합산)

### 10-2. 발동 방식 [원문 + 추가]
- 스킬 키를 누르면 **마우스 포인터 방향**으로 발동. 방향이 필요 없는 스킬은 즉시 발동 [원문]
- **논타겟과 타겟 스킬 모두 존재** [원문]
  - 논타겟: 투사체·범위. 지면에 조준 표시(설정에서 "빠른 시전"과 "표시 후 시전" 선택 [추가])
  - 타겟: 커서 근처 24px 안의 적/아군 자동 선택. 대상이 없으면 시전 불가 안내
- [추가] 시전 형태: 즉시 / 캐스팅(이동 시 취소) / 채널링(유지) / 차지(누르고 떼기) / 설치
- [추가] 선딜·후딜이 있어 "읽고 피할 수 있는" 액션성을 확보한다. 적 몹의 강한 스킬은 바닥 경고 장판을 0.6~1.2초 먼저 보여준다

### 10-3. 숙련도와 레벨업 [원문 + 공식 추가]
- **숙련도**: 스킬을 사용하거나, 그 스킬로 적에게 영향을 줬을 때(피해·CC·힐·버프) 오른다 [원문]
  - 사용 1회 +1, 적중 대상 1명당 +2, 처치 기여 +5, 힐·버프 대상 1명당 +2 (몹 등급 배율: 일반 1 ~ 대재앙 10)
  - 획득량 `× (1 + 해당계열잠재력/100)`
- **스킬 레벨업**: 숙련도가 현재 레벨 최대치를 넘으면 레벨업. **한 번에 많이 오르면 여러 레벨 연속 상승** [원문]
  - `필요숙련도(Lv) = floor(30 × Lv^1.5)`
  - 스킬 레벨 ≤ 플레이어 레벨 [원문]. 넘치는 숙련도는 최대 1레벨분까지 보관
  - 스킬 레벨당 피해·효과 +4%, 5레벨마다 쿨 −3%
- **잠재력**
  - 첫 습득 시 시작 레벨 = `1 + floor(잠재력/40)` (플레이어 레벨 이하)
  - 스킬 습득 시 잠재력 상승 [원문: 난이도별 차등]: 하급 +1, 중급 +3, 상급 +6, 초월급 +12 (해당 계열 잠재력에)
- **스킬 습득 경로** [추가]: 전직 시 기본 지급, 레벨 달성, 스킬북 아이템(드롭·상점), 퀘스트 보상, 스킬 교관 NPC(RUC 지불)

- **+10 달성** [원문]: 아이템에 **특색 있는 이름**이 붙는다. 형식 `「접두어」 아이템명 +10` — 접두어는 아이템 테마·속성 기반 풀에서 생성(예: "새벽을 가르는", "정령왕의", "꺼지지 않는 불씨의")
- **서버 전체 공지** [원문]: `'<이름>이 <아이템> 아이템 10강에 성공했습니다'` → 조사 자동 처리(`이/가`). 화면 상단 금색 배너 + 채팅 시스템 메시지 + 알림
- 연출: 성공 시 빛 폭발, 실패 시 연기, 파괴 시 유리 깨지는 이펙트(밝은 톤, 과장된 코믹 연출)
- 확률 판정은 서버 CSPRNG로 하고 모든 결과를 로그에 남긴다

### 16-2. 마법부여 [원문]

### 17-1. RUC [원문 + 베타 정책 해석]

  - `RUC_MODE=beta`(기본값): RPG 전용 베타 지갑을 사용한다. 이름 표시는 "RUC"로 동일하게 하되 실제 MC 잔액과 분리. 베타가 끝나면 초기화하거나 일부 환산

- 인원 보정: 몹 HP `× (1 + 0.6×(인원−1))`

### 20-4. 던전 진행 규칙 [추가]

- 몹 AI 상태: 대기 → 순찰 → 추적 → 공격 패턴 → 귀환(리쉬). 보스는 패턴 스크립트 데이터(JSON 타임라인)로 정의

2. 반복 요소는 프로시저럴하게 생성: 희귀도별 팔레트 스왑, 속성별 이펙트 색 교체, 좌우 방향 중 대칭 가능한 부분은 미러링(비대칭 장비는 개별 정의)
3. 빌드 스크립트(`scripts/build-atlas.ts`, `pngjs` 또는 `canvas`)로 **텍스처 아틀라스 PNG + JSON(PixiJS spritesheet 형식)**을 생성
4. 시트 배열: 캐릭터 시트 1장 = 행(방향 8: S, SE, E, NE, N, NW, W, SW) × 열(동작 × 4프레임)
5. 나중에 실제 아티스트 PNG로 바꿔 끼울 수 있게 **에셋 ID 기반으로 로드**(코드가 파일 경로를 직접 참조하지 않음)
6. `/rpg/dev/gallery`(개발 모드 전용) 페이지에서 모든 스프라이트·아이콘·애니메이션을 미리 볼 수 있게 한다

**아트 방향**: 밝은 판타지 픽셀. 외곽선은 어두운 채도 색(순수 검정 금지), 광원은 왼쪽 위, 3~4단계 명암. 사운드는 8/16비트풍 효과음(무료 라이선스 또는 jsfxr류 생성), BGM은 광장(따뜻한 루트), 필드(경쾌), 던전(긴장), 보스.
