# [DEFINE] 항목 설계 제안

원본 명세에서 `[DEFINE: ...]`로 위임된 항목 전부에 대한 구체안입니다. 각 항목은 **수정 가능한 제안**이며, 확정되면 해당 Phase에서 그대로 구현합니다.

---

## D1. 홈 서버 구성 요소 (§2.3)

허브의 목적은 하나입니다 — **처음 온 사람이 30초 안에 "어디로 갈지" 정하게 만드는 것.** 그 기준으로 구성했습니다.

### 필수 (Phase 2에 포함)

| 요소 | 설계 |
|---|---|
| **서버 선택 NPC 4체** | 광장 중앙 분수 주변에 레이드/국가전/평화 NPC 배치. 클릭 시 확인 GUI → 이동. 머리 위 홀로그램에 `현재 12/60명` 실시간 표시 |
| **나침반 GUI** | 인벤토리 5번 슬롯 고정 나침반 → 우클릭 시 서버 선택 메뉴. NPC까지 안 걸어가도 되게 |
| **정보 보드** | 광장 진입 정면 벽. 좌측=공지, 우측=업데이트 로그. 관리자가 `/공지작성`으로 갱신 |
| **랭킹 벽 3면** | XP 랭킹 / 길드 랭킹 / 평판 상위. 홀로그램 텍스트, 10분마다 갱신 |
| **최초 접속 튜토리얼** | 첫 접속자만 진입하는 짧은 안내 동선(5지점). 끝에서 시작 자금 1,000 Ruc 지급. 완료 여부 DB 저장 |
| **신규/복귀 구분 스폰** | 첫 접속 → 튜토리얼, 재접속 → 바로 광장 |

### 권장 (Phase 9)

| 요소 | 설계 |
|---|---|
| **Ruc 상점 NPC** | 코스메틱·편의 아이템만. **장비/전투 아이템 판매 금지**(§5 P2W 방지 원칙) |
| **일일 보상 NPC** | 출석 연속 보너스. MOOKI의 `출석체크`를 인게임으로 옮겨오는 것 |
| **코스메틱 존** | 파쿠르 코스(기록 랭킹), 낚시터, 사진 스팟 |
| **후원자 라운지** | MVP 등급 이상만 입장 가능한 별도 구역 (D7 연계) |
| **AFK 구역** | 5분 무동작 시 자동 이동, 인원 카운트에서 제외 |

## D2. 코어(Core) 제작 체인 (§3.1)

**설계 의도:** 코어는 영토를 만드는 물건이므로 **혼자서는 절대 못 만들어야** 합니다. 전투 자원(네더라이트) + 탐험 자원(에코 파편) + 화폐(Ruc)를 전부 요구해서, 길드가 역할을 나누도록 강제합니다.

### 최종 조합: 코어 (Core)

```
  [ 강화 장갑판 ] [ 영토 렌즈 ] [ 강화 장갑판 ]
  [ 영토 렌즈   ] [ 네더의 별 ] [ 영토 렌즈   ]
  [ 강화 장갑판 ] [ 국가 인장 ] [ 강화 장갑판 ]
```

### 하위 부품

| 부품 | 재료 | 획득처 |
|---|---|---|
| **강화 장갑판** ×4 | 네더라이트 조각 ×4 + 흑요석 ×4 | 네더 탐사 (레이드/국가전) |
| **영토 렌즈** ×3 | 엔드 크리스탈 ×1 + 자수정 조각 ×4 + 에코 파편 ×1 | 엔드 + 고대 도시 |
| **국가 인장** ×1 | **제작 불가.** 국가전 서버 인장 NPC에게서 **250,000 Ruc**에 구매 | 길드장만 구매 가능 |
| **네더의 별** ×1 | 바닐라 (위더) | — |

### 코어 규칙

- **길드 귀속**: 다른 길드원이 들면 아무 기능 없음, 상자에 넣을 수 없음
- **1회용**: 설치 순간 소모. 파괴되어도 회수 불가
- **길드장/부길드장만 설치 가능**
- **설치 가능 지점 제한**: 맵에 미리 지정된 코어 거점에서만. 아무 데나 못 박음
- **전쟁 시간대에만 설치 가능**

> 목표 비용: 길드 하나가 **일주일 정도** 모아야 코어 1개. 첫 시즌 운영 데이터 보고 조정.

## D3. 드래곤 알 버프 세트 (§3.1)

**설계 의도:** 강력하되 **숨길 수 없어야** 합니다. 소지자가 잠수로 버프만 빨아먹으면 콘텐츠가 죽으므로, 항상 추적당하는 대가를 붙였습니다. 네트워크 전역에 **레이드 1개 + 평화 1개, 총 2개만** 존재합니다.

### 버프 (인벤토리에 소지 중일 때, 어느 서버에 있든 적용)

| 효과 | 수치 |
|---|---|
| 최대 체력 | +4 (하트 2칸) |
| 성급함 (Haste) | I |
| Ruc 획득량 | +15% |
| 자체 XP 획득량 | +10% |
| 전투 해제 후 재생 | 비전투 10초 경과 시 재생 I |

### 대가 (밸런스 장치)

| 제약 | 내용 |
|---|---|
| **위치 노출** | 30초마다 반경 200블록 내 전원에게 발광 효과로 표시 |
| **네트워크 공지** | 하루 1회 정해진 시각, 전 서버에 현재 소지자 닉네임 방송 |
| **보관 불가** | 상자·엔더상자·셜커 등 어떤 컨테이너에도 넣을 수 없음 (창고 사재기 차단) |
| **사망 시 드랍** | 소지자 사망 시 무조건 바닥에 드랍 |
| **평화 서버 예외** | 평화 서버는 PvP가 없으므로 여기 있는 알은 **72시간마다 강제 리스폰 지점으로 회수**. 한 명이 영구 독점 못 함 |

## D4. 평판 상승 방법 2가지 (§3.7)

평판은 "낯선 사람을 믿어도 되는가"의 신호입니다. 그래서 **돈으로 못 사고, 시간만으로도 안 오르고, 다른 사람의 인정이 필요하게** 설계했습니다.

### 방법 1 — 유효 신고 (Verified Report)

내가 제출한 신고가 **스태프 검토를 거쳐 실제 제재로 이어지면** 평판 점수 상승.

- 유효 신고 1건당 **+15점**
- 허위/장난 신고 1건당 **−25점** (신고 남발 방지 — 페널티가 더 큼)
- 스태프 재량 판정, 신고자에게 결과 DM 통보

### 방법 2 — 주간 추천제 (Weekly Endorsement)

`/추천 [닉네임]` — 같이 플레이한 사람을 추천합니다.

- **주 1회**, 계정당 1표만. 같은 사람에게는 4주에 1번만
- 자격 조건: **해당 주에 그 사람과 같은 서버에서 20분 이상 동시 접속** (모르는 사람 품앗이 차단)
- 가중치: 추천한 사람의 평판 티어가 높을수록 점수가 큼 (초록 +12 / 노랑 +8 / 빨강 +4 / 보라 이하 0)
- 상호 추천(A↔B)은 양쪽 모두 **50% 감점 적용** (짬짜미 방지)

### 티어 구간 (제안)

| 티어 | 점수 | 의미 |
|---|---|---|
| 🟢 초록 | 300+ | 최상위 신뢰 |
| 🟡 노랑 | 150~299 | 양호 |
| 🔴 빨강 | 50~149 | **신규 기본값** |
| 🟣 보라 | 0~49 | 주의 |
| 🔵 파랑 | −100~−1 | 경고 이력 |
| 🟦 남색 | −300~−101 | 제재 이력 다수 |
| ⬛ 검정 | −301 이하 | 거래·길드 가입 제한 |

> 신규가 최상위(초록)에서 시작해 떨어지는 구조면 "신규 = 초록"이 되어 신호로 못 씁니다. 그래서 **중간(빨강)에서 시작해 올라가는 구조**로 잡았습니다.

## D5. 제재 티어 4~10 (§3.9)

1~3단계는 원안 그대로, 4단계부터 설계했습니다.

| 단계 | 디스코드 | 마인크래프트 | 재화 몰수 | 추가 |
|---|---|---|---|---|
| 1 | 뮤트 6시간 | 밴 6시간 | — | — |
| 2 | 뮤트 12시간 + 밴 12시간 | 밴 1일 | — | — |
| 3 | 뮤트 3일 + 밴 3일 | 밴 3일 | 10% | — |
| **4** | 뮤트 7일 + 밴 7일 | 밴 7일 | 20% | 평판 −50 |
| **5** | 밴 14일 | 밴 14일 | 35% | 평판 1티어 강등, 길드 직책 박탈 |
| **6** | 밴 30일 | 밴 30일 | 50% | 길드 강제 탈퇴, 영토 청구권 상실 |
| **7** | 밴 90일 | 밴 90일 | 70% | 모든 `/home`·클레임 삭제, 후원 혜택 정지 |
| **8** | 영구 밴 | 밴 180일 | 100% | 레이드/평화 인벤토리 전체 몰수, 평판 검정 고정 |
| **9** | 영구 밴 | **영구 밴** | 100% | 계정 데이터 아카이브 후 비활성, 소명 절차 1회만 |
| **10** | 영구 밴 | **영구 밴 + IP 차단** | 100% | 부계정 연쇄 차단, 사안 기록 보존 |

### 단계별 적용 기준 (예시)

- **1~3**: 욕설, 경미한 트롤링, 채팅 도배
- **4~5**: 반복 괴롭힘, 평화 서버 간접 살해 시도, 광고
- **6~7**: 버그 악용, 재화 복사, 조직적 그리핑
- **8~9**: 핵/치트 사용, 현금거래(RMT), 사기
- **10**: 핵 배포, 서버 공격(DDoS 등), 개인정보 유출, 제재 회피 상습

### 운영 원칙

- 4단계 이상은 **Manager 이상 승인 필요**. Helper 단독 집행 불가
- 모든 제재는 **증거(스크린샷/로그) 첨부 필수**, 티켓 채널에 기록 보존
- 8단계 이상은 **소명 창구**를 반드시 남김 (오판 복구 경로)
- **10단계 IP 차단 주의**: IP는 개인정보에 해당하고, 공유 IP(학교·PC방·통신사 CGNAT)에서는 무고한 사람이 같이 막힙니다. 최후 수단으로만, 보관 기간을 정해두고 사용하세요.

## D6. MOOKI 봇 정리 (§4.1)

### 제거 — 경제 미니게임 (서버 관리와 무관)

```
/가입  /탈퇴  /출석체크  /주식  /랭크  /인벤토리  /재화
/창업  /상장  /인수  /ruc지급  /프로필
```
관련 코드: `economy_data.json`, `calculateInflationMultiplier()`, `generateTextChart()`, `updateStockPrice()`, 프로필 카드 캔버스 렌더링

> ⚠️ **다만 `/프로필`의 캔버스 렌더링 코드는 남겨두길 권장합니다.** 나중에 "인게임 Ruc 잔고 + 평판 + XP 레벨" 프로필 카드로 재활용할 수 있습니다. 경제 로직만 걷어내고 렌더러는 보존.

### 유지

- 보안 모듈 (스팸/피싱/대량멘션/레이드 탐지) — 이미 잘 되어 있음
- 티켓 시스템 — §3.8 신고 시스템의 기반
- 반응 역할, 임베드 빌더, 채널 설정

### 추가 — 관리 기능

| 명령어 | 기능 |
|---|---|
| `/인증` | **마크 계정 연동.** 인게임 `/인증` → 6자리 코드 → 디스코드에 입력. 이후 모든 제재·평판·중계가 한 사람으로 묶임. **가장 먼저 만들어야 할 것** |
| `/제재 [유저] [단계] [사유]` | D5 티어 자동 집행. 디스코드 뮤트/밴 + RCON으로 마크 밴 + 재화 몰수를 **한 번에** |
| `/기록 [유저]` | 경고·제재·신고 이력 전체 조회 |
| `/경고 [유저] [사유]` | 누적 경고. 3회 누적 시 자동으로 1단계 제재 제안 |
| `/평판 [유저]` | 평판 점수·티어·변동 이력 |
| `/서버상태` | 4개 서버 온라인/인원/TPS 임베드 |
| `/공지 [채널] [내용]` | 임베드 공지 + 역할 멘션. 예약 발송 지원 |
| `/정화 [개수]` | 메시지 일괄 삭제 |
| `/슬로우 [초]` · `/잠금` | 채널 통제 (레이드 대응) |
| `/역할일괄 [역할] [대상]` | 역할 일괄 지급/회수 |
| 자동 입장 역할 | 신규 입장 시 기본 역할 + 평판 "빨강" 역할 자동 부여 |
| 감사 로그 채널 | 모든 관리 행위를 전용 채널에 자동 기록 |

### 기술 부채 정리 (동시 진행)

- 912줄 단일 파일 → `commands/`, `events/`, `lib/` 분리
- JSON 파일 저장 → MySQL (마크 서버와 동일 DB. 경합 조건 및 파일 손상 방지)
- **`client.on('error')` + `unhandledRejection` 핸들러 추가** — 현재 크래시 원인
- 모든 인터랙션 핸들러를 try-catch로 감싸고 실패 시 사용자에게 응답

## D7. 후원 등급 혜택 (§5.3)

### 대원칙 — Pay-to-Win 금지

**전투 능력치, 장비, 전쟁 유불리에 영향을 주는 것은 어떤 등급에서도 판매하지 않습니다.** 판매하는 것은 오직 3가지입니다 — **꾸미기 / 편의 / 소속감.**

> ⚠️ 단, **Ruc 충전을 파는 이상(§5.1) Ruc로 전투 장비를 살 수 있으면 그 순간 P2W입니다.** Ruc 상점은 코스메틱·편의·소모품으로 한정하고, 전투 장비·강화 재료·코어 부품은 **Ruc로 살 수 없게** 막아야 합니다. (`국가 인장`만 예외 — 길드 단위 대량 소모처로 의도적으로 남김)

| | **Ruc** (무료) | **VIP** | **SVIP** | **MVP** | **Prime** | **Premium** | **Elite** |
|---|---|---|---|---|---|---|---|
| `/home` 개수 | 1 | 2 | 3 | 5 | 8 | 12 | 20 |
| `/tpa` 쿨타임 | 60초 | 45초 | 30초 | 20초 | 15초 | 10초 | 5초 |
| 접속 대기열 | 일반 | 우선 1 | 우선 2 | 우선 3 | 우선 4 | 우선 5 | 최우선 |
| 채팅 네임 색상 | — | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 코스메틱 파티클 | — | 3종 | 8종 | 20종 | 40종 | 전체 | 전체 + 은퇴 세트 |
| `/hat` (머리 착용) | — | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

## D10. 디스코드 인증 의무화 (신규 요구사항, 2026-09-12)

**목적:** 그리핑·부계정 공격 차단.
**채택 방식:** **로비 격리 후 인증** — 접속은 되지만 인증 전까지 홈 서버 인증 구역에 묶입니다.

### 왜 이 방식인가

| 방식 | 그리핑 차단 | 유입 장벽 | 판정 |
|---|---|---|---|
| 접속 자체를 차단(화이트리스트) | 최상 | **매우 높음** — 구경하러 온 사람이 전부 튐 | ✗ |
| **로비 격리 후 인증** | **최상** | 중간 — 서버 분위기는 보여주면서 행동만 막음 | ✅ **채택** |
| 홈만 허용, 이동 시 인증 | 중 | 낮음 | ✗ 홈에서의 채팅 스팸을 못 막음 |

격리 방식도 차단 효과는 화이트리스트와 동일합니다. **인증 전에는 블록 상호작용·채팅·이동이 전부 막히므로 피해를 줄 수단이 없기 때문입니다.** 대신 서버를 눈으로 보여줄 수 있어서 이탈률이 훨씬 낮습니다.

### 흐름

```
1. 접속 → Velocity가 홈 서버로 라우팅
2. RucCore가 DB 조회: 이 UUID가 디스코드 계정과 연동되어 있는가?
   └ 연동됨   → 광장으로 바로 통과
   └ 미연동   → 인증 구역에 스폰 + 6자리 코드 발급
3. 화면에 코드 표시 (타이틀 + 채팅 + 보스바에 남은 시간)
4. 플레이어가 디스코드 #인증 채널에서  /인증 123456  입력
5. MOOKI가 코드 검증 → DB에 (디스코드ID ↔ 마크UUID) 기록
6. 서버가 감지 → 격리 해제 → 광장으로 텔레포트 + 시작 자금 1,000 Ruc
```

### 인증 구역 제약 (미인증 상태)

| 항목 | 상태 |
|---|---|
| 이동 | 구역 밖으로 나가면 즉시 되돌림 |
| 채팅 | 차단 (안내 메시지만 반복 표시) |
| 블록 파괴/설치 | 차단 |
| 아이템 드랍/픽업 | 차단 |
| 명령어 | `/인증`, `/help` 만 허용 |
| 서버 이동 | 차단 (NPC·나침반 비활성) |
| 다른 플레이어와 상호작용 | 불가 (별도 구역이라 만날 일 없음) |

### 코드 규격

| 항목 | 값 |
|---|---|
| 형식 | 숫자 6자리 |
| 유효시간 | 10분 |
| 동시 발급 | 계정당 1개 (재요청 시 기존 코드 무효화) |
| 재요청 제한 | 60초 쿨다운 |
| 시도 제한 | 5회 실패 시 10분 잠금 (무차별 대입 차단) |
| 바인딩 | 발급을 요청한 **마크 UUID에만** 유효 |

### 실제 그리핑 차단 장치 — 1:1 연동

**핵심은 코드 입력이 아니라 "디스코드 계정 하나 = 마크 계정 하나" 규칙입니다.**

- 이미 연동된 디스코드 계정으로는 다른 마크 계정을 인증할 수 없음
- 이미 연동된 마크 계정은 다른 디스코드로 갈아탈 수 없음 (해제는 스태프만)
- **제재 연동**: 디스코드 계정이 밴되면 연동된 마크 계정도 자동 밴, 반대도 동일
- 부계정을 만들려면 **새 디스코드 계정(전화번호 인증 필요)**이 있어야 함 → 이게 실질적 장벽

### 추가 가입 조건

MOOKI에 이미 있는 보안 모듈을 재사용합니다.

- 디스코드 계정 생성 후 **7일 이상** (`MIN_ACCOUNT_AGE_DAYS` 기존 상수 재사용)
- 디스코드 서버에 **실제 가입한 멤버**여야 함 (나갔다 들어온 유령 계정 차단)
- 평판 "검정" 등급은 인증 자체를 거부

### ⚠️ 반드시 지켜야 할 기술 전제

**`server.properties`의 `online-mode=true`가 필수입니다.**

오프라인 모드(크랙 허용)로 운영하면 **UUID를 마음대로 위조할 수 있어서 이 인증 체계 전체가 무의미해집니다.** 남의 인증된 계정 이름으로 접속하면 그대로 통과됩니다. 정품 인증이 UUID 신뢰의 유일한 근거입니다.

프록시를 쓰므로 정확히는:
- Velocity: `online-mode = true`, `player-info-forwarding-mode = "modern"`
- 각 백엔드 Paper 서버: `online-mode=false` + `paper-global.yml`에서 `velocity.enabled: true` + 시크릿 공유

(백엔드가 `false`인 건 정상입니다 — 프록시가 이미 인증했고 서명된 정보를 전달하기 때문입니다. 단 **백엔드 포트가 외부에 노출되면 안 됩니다.** 방화벽으로 프록시 포트만 열어야 합니다.)

### ⚠️ 가용성 위험

이 설계는 **MOOKI 봇이 죽으면 아무도 새로 들어올 수 없다**는 뜻입니다. 신규 유입이 통째로 막힙니다.

대응:
1. Phase 0에서 넣은 전역 오류 핸들러로 봇이 쉽게 죽지 않게 함 (완료)
2. 봇 프로세스 자동 재시작 (pm2 또는 systemd)
3. **스태프 수동 인증 명령** `/인증승인 [플레이어]` — 봇의 DB 기록 없이 스태프가 직접 통과시킬 수 있는 우회로
4. 봇 미응답이 2분 이상 지속되면 인증 구역에 "현재 인증 시스템 점검 중" 안내 표시

### 구현 위치

| 구성요소 | 담당 |
|---|---|
| 인증 구역 격리, 코드 발급/표시 | `RucHome` (Phase 2) |
