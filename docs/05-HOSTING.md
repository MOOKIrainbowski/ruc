## 1. 먼저 — 이 서버가 호스팅에 요구하는 것

비교표를 보기 전에 **무엇을 돌려야 하는지**부터 못박아야 합니다. 이것이 선택지의
절반을 바로 탈락시킵니다.

| 프로세스 | 메모리 (현재 로컬 설정) |
|---|---|
| Velocity 프록시 | 256M ~ 512M |
| home (허브) | 1G ~ 2G |
| raid (약탈) | 1G ~ 2G |
| war (국가전) | 512M ~ 1G |
| peace (평화) | 512M ~ 1G |
| MySQL (9a 에서 H2 → MySQL 전환) | ~512M |
| MOOKI 디스코드 봇 (Node.js) | ~150M |
| OS · 여유 | ~2G |
| **합계** | **약 10~12GB** |

**결론 1 — 관리형 마인크래프트 호스팅은 쓸 수 없습니다.**
Apex / Shockbyte / BisectHosting 같은 곳은 "마인크래프트 서버 인스턴스 하나"를
팝니다. 임의의 프로세스(Velocity 프록시, MySQL, Node 봇)를 올릴 수 있는 셸을
주지 않습니다. 서버를 4개 사면 프록시로 묶을 방법이 없고, 봇은 따로 호스팅해야
합니다. **VPS 또는 전용 서버가 필요합니다.**

**결론 2 — 코어 수보다 단일 코어 성능이 중요합니다.**
마인크래프트 서버는 월드의 틱 루프가 **한 코어에서** 돕니다. 코어 16개짜리
느린 CPU보다 코어 4개짜리 빠른 CPU가 낫습니다. 우리는 서버가 4개라 코어도
4개 이상 필요하지만, "vCPU 많음"을 성능으로 읽으면 안 됩니다.

**결론 3 — 위치는 서울입니다.**
한국 플레이어 기준 서울 리전은 10ms 이하, 도쿄는 30~40ms 가 더 붙습니다.
PvP(약탈·국가전)가 핵심인 서버라 이 차이가 체감됩니다.

## 3. 추천 — **iwinv (스마일서브) 서울 VPS, 12~16GB**

**왜 이것인가**

1. **서울에 있습니다.** 플레이어가 한국인이고 PvP 가 핵심이면 이게 첫 번째
   조건입니다. 도쿄와 30~40ms 차이는 약탈 서버에서 그대로 드러납니다.
2. **한 대에 전부 올라갑니다.** 프록시 + 백엔드 4개 + MySQL + 디스코드 봇이
   같은 기계에 있으면 `127.0.0.1` 로 묶입니다. 지금 로컬 구성이 **그대로**
   올라가고, RCON·DB 가 인터넷을 타지 않아 보안도 단순해집니다.
3. **국내 결제.** 카드·계좌이체가 됩니다. 해외 카드 문제나 환율 변동이 없습니다.
4. **가격.** 같은 국내 서울 기준으로 마크호스팅(₩120,000/16GB)보다 확실히
   쌉니다. 8GB 기준 ₩45,100 이면 16GB 도 ₩80,000 대로 예상되지만 **이건
   확인이 필요합니다.**

**계약 전에 반드시 물어볼 것 3가지**

- **16GB(또는 12GB) 플랜의 월 요금**과 vCPU 수
- **DDoS 방어**가 포함인지, 아니면 별도 상품인지 — 마인크래프트 서버는
  공격을 받습니다. 이게 없으면 다른 곳이 낫습니다
- **트래픽 과금** 여부 (종량제면 월 예상 비용이 크게 달라집니다)

**대안 두 가지**

- DDoS 방어를 별도로 사야 한다면 → **마크호스팅(mcok)**. 비싸지만 DDoS 무제한
  방어를 명시하고 RAID 1+0 이중화를 제공하며, 국내 마크 서버 운영에 특화돼
  있어 문의가 빠릅니다. RDP/SSH 를 주므로 우리 구성이 전부 올라갑니다.
- 해외 카드가 괜찮고 콘솔·스냅샷이 편한 쪽이 낫다면 → **Vultr Seoul 16GB
  (약 $80/월)**. 스냅샷·방화벽·API 가 잘 갖춰져 있습니다.

**추천하지 않는 것**

- **Oracle 무료 티어** — 런칭용으로는 쓰지 마세요. 2 OCPU 에 마크 서버 4개는
  코어 경쟁이 납니다. 무료 자원은 용량이 없을 때 생성이 거부되고, 예고 없이
  정책이 바뀝니다(실제로 2026-06 에 반토막). **테스트용으로는 훌륭합니다.**
- **관리형 마크 호스팅** — 프록시·MySQL·봇을 못 올립니다. 위 §1 결론 1.

## 4. 이전 안내 (로컬 → 호스팅)

### 4.1 옮기기 전 (로컬에서 할 일)

**9a 런칭 전제 조건을 먼저 끝내세요.** 이전 자체보다 이게 먼저입니다.

- [ ] `database.type` 을 `h2` → `mysql` 로 (5곳: 서버 4개 + `proxy/plugins/rucgate`)
- [ ] RCON 비밀번호를 `ruc-<서버>-local-dev` 에서 **실제 비밀번호로 교체**
      (서버 4개의 `server.properties` + 봇 `.env` 의 `RUC_RCON_PW`)
- [ ] `online-mode` 확인 — 프록시가 `true`, 백엔드는 `false` + forwarding secret
- [ ] 월드·DB 백업 자동화

### 4.2 서버에 올리기

```bash
# 1. 필수 패키지
sudo apt update && sudo apt install -y openjdk-21-jre-headless mysql-server nodejs npm

# 2. 파일 업로드 (로컬에서)
#    world* 폴더가 크므로 압축해서 옮깁니다.
scp -r minecraft/ user@서버IP:~/ruc/
scp -r "MOOKI(General-purpose Discord server bot)/" user@서버IP:~/ruc/mooki/

# 3. MySQL 준비
sudo mysql -e "CREATE DATABASE ruc CHARACTER SET utf8mb4;"
sudo mysql -e "CREATE USER 'ruc'@'localhost' IDENTIFIED BY '<강한-비밀번호>';"
sudo mysql -e "GRANT ALL ON ruc.* TO 'ruc'@'localhost'; FLUSH PRIVILEGES;"
```

### 4.3 방화벽 — **여기가 가장 중요합니다**

밖에서 열려 있어야 하는 포트는 **25565 하나뿐**입니다.

```bash
sudo ufw allow 22/tcp        # SSH
sudo ufw allow 25565/tcp     # 마인크래프트 (프록시)
sudo ufw enable
```

25566~25569(백엔드)와 25576~25579(RCON)는 **절대 열지 마세요.**
백엔드에 직접 붙을 수 있으면 디스코드 인증(D10)이 통째로 우회됩니다.
`server-ip=127.0.0.1` 설정도 그대로 유지하세요.

### 4.4 서버 설정에서 바꿀 것

| 파일 | 바꿀 것 |
|---|---|
| `proxy/velocity.toml` | `bind = "0.0.0.0:25565"` (로컬은 127.0.0.1 이었을 수 있음) |
| `servers/*/server.properties` | `rcon.password` 를 실제 비밀번호로 |
| `servers/*/plugins/RucCore/config.yml` | `database.type: mysql` + 접속 정보 |
| `proxy/plugins/rucgate/config.*` | 같은 MySQL 정보 |

### 4.5 봇 설정 — **.env 두 줄만 고치면 됩니다**

호스팅으로 옮겨도 **코드는 고치지 않습니다.** 주소가 전부 설정에 있습니다.

```dotenv
# 봇이 마크 서버와 같은 기계에 있다면 그대로 127.0.0.1 입니다.
RUC_RCON_HOST=127.0.0.1
RUC_RCON_PW=<새 RCON 비밀번호>

# /서버상태 가 볼 주소. 같은 기계면 127.0.0.1:25565 그대로.
MC_STATUS_HOST=127.0.0.1
MC_STATUS_PORT=25565

# 사람에게 보여 줄 접속 주소 — 여기만 도메인으로 바꿉니다.
MC_PUBLIC_ADDRESS=play.rucserver.kr
```

**봇을 다른 기계에 둔다면** `RUC_RCON_HOST` 와 `MC_STATUS_HOST` 를 서버의 공인
IP 로 바꾸고, RCON 포트를 **그 IP 에서만** 접근 가능하게 방화벽을 좁히세요.
RCON 은 평문 프로토콜이라 인터넷에 노출하면 안 됩니다. 가능하면 봇을 같은
기계에 두는 편이 훨씬 안전합니다 — 추천안이 그래서 VPS 입니다.

### 4.6 상시 실행 (systemd)

```ini
# /etc/systemd/system/mooki.service
[Unit]
Description=MOOKI Discord Bot
After=network.target

[Service]
Type=simple
User=ruc
WorkingDirectory=/home/ruc/mooki
ExecStart=/usr/bin/node MOOKIbot.js
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now mooki
sudo journalctl -u mooki -f     # 로그 보기
```

마크 서버 4개와 프록시도 같은 방식으로 유닛을 만들되, **프록시는 백엔드가 다
뜬 뒤에 시작**해야 합니다 (`After=` 와 `ExecStartPre=` 로 대기).

### 4.7 도메인

`play.rucserver.kr` 같은 주소를 쓰려면:

- **A 레코드** → 서버 공인 IP
- 25565 가 아닌 포트를 쓴다면 **SRV 레코드** (`_minecraft._tcp.play`)

도메인을 쓰면 나중에 서버를 옮길 때 플레이어에게 새 주소를 알릴 필요가 없습니다.
웹사이트의 `NEXT_PUBLIC_MC_ADDRESS` 와 봇의 `MC_PUBLIC_ADDRESS` 도 이 값으로
맞추세요.

### 4.8 옮긴 뒤 확인

### 바뀐 추천 — **Oracle Cloud Always Free (서울 리전)**

§3 에서 Oracle 무료 티어를 **런칭용으로 비추천**했습니다. 근거는 두 가지였고,
지금은 하나가 사라졌습니다.

| 그때 걱정 | 지금 |
|---|---|
| "2 OCPU 에 마크 서버 4개는 코어 경쟁" | **서버가 2개입니다.** OCPU 하나당 서버 하나 — 마크는 월드 틱이 한 코어에서 도니 이 배분이 정확히 맞습니다 |
| "12GB 로는 빠듯" | **7~8GB 면 충분합니다.** 여유 4GB |
| ARM64 아키텍처 | **문제 없습니다.** Paper·Velocity·플러그인은 전부 자바 바이트코드라 아키텍처를 타지 않습니다. MySQL·Node 도 ARM 빌드가 정식 제공됩니다. ARM 이 문제가 되는 건 네이티브 모드 로더 쪽인데 우리는 플러그인만 씁니다 |

**남은 위험은 그대로입니다. 이건 알고 들어가야 합니다.**

- **용량이 없으면 생성이 거부됩니다.** 서울 리전의 무료 A1 은 인기가 많아
  "Out of host capacity" 가 자주 납니다. 될 때까지 재시도해야 합니다.
- **정책이 예고 없이 바뀝니다.** 2026-06-15 에 4 OCPU/24GB → 2 OCPU/12GB 로
  반토막 났는데 **공지가 없었습니다.** 또 줄어들 수 있습니다.
- **유휴 자원 회수 정책**이 있습니다. 마크 서버는 상시 CPU 를 쓰므로 유휴로
  분류될 일은 거의 없지만, 플레이어가 아무도 없는 기간이 길면 확인이 필요합니다.
- **춘천(South Korea North)은 무료 A1 대상이 아닙니다.** 서울(ap-seoul-1)로
  만드세요.

→ **백업을 반드시 자동화하세요.** 무료 티어는 SLA 가 없습니다. 월드와 DB 를
외부(구글 드라이브·개인 PC)로 주기 백업해 두면, 최악의 경우에도 유료로 옮겨서
그대로 띄울 수 있습니다. 이건 §4.1 의 9a 항목이기도 합니다.
