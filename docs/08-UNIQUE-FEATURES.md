# 러크만의 기능 — 제안 · 계획 (2026-10-09)

## 왜

랜딩의 "하나의 지갑 · 도망은 없다 · 돈으로 못 사는 강함" 은 다른 서버에도 있는 말입니다 (공용 화폐 · 전투로그 처벌 · 무과금 강함).
러크에만 있는 재료는 따로 있습니다 — **7색 평판(디스코드 역할과 연동)**, **네트워크에 단 하나인 드래곤 알**,
**마크 · 디스코드 · 웹이 하나로 묶인 구조**. 아래 제안은 전부 이 재료를 서로 엮는 것입니다 (새 장르를 붙이지 않음).

원칙 (D7): 돈으로 사는 전투 이득 없음 · 악용(부계정 · 짬짜미)을 먼저 막고 시작 · 지금 운영 중인 **홈 · 약탈**에서 돌아갈 것.

## 소유자 결정 (2026-10-09)

- **A · B · C · D 전부 승인.** 웹 연결은 **① 디스코드 채널 경유**. 연대기(E)는 나중에.
- 구현 순서: C → D → A → B (작은 것부터). 게임 안 확인 후 웹 문구 교체.

## 제안

### A. 평판 현상금 — "평판이 나쁘면 목에 값이 붙는다" ★ 추천

| 항목 | 내용 |
|---|---|
| 규칙 | 평판 **보라 이하**인 사람은 약탈 서버에서 자동으로 **현상수배**. 이름표 · 스코어보드에 `수배`, 위치는 2분마다 대략(청크 범위)만 공지 |
| 현상금 | 제재로 **몰수된 Gold** 가 현상금 풀로 갑니다 (지금은 그냥 사라짐). 수배자를 처치하면 풀에서 지급 |
| 수배 해제 | 평판이 빨강으로 회복되면 해제. 처치당하면 24시간 수배 면제 (계속 사냥당하는 것 방지) |
| 악용 방지 | 같은 사람을 다시 잡아 받는 건 24시간 1번 · 디스코드 인증 · 레벨 10 이상만 지급 · 부계정끼리 주고받기는 규칙 0.9 · 0.12 로 회수 |
| 왜 러크만 | 평판(디스코드 역할까지 연동)이 **약탈 콘텐츠를 만들고**, 제재 몰수가 **경제로 돌아오는** 구조. 다른 서버의 현상금은 플레이어가 돈 걸고 끝 |
| 손댈 곳 | RucRaid (수배 · 지급) · RucCore 평판 읽기 · `SanctionService` 몰수 → 풀 적립 · 디스코드 중계에 "수배 / 처치" 임베드 |
| 크기 | 중 (약 2~3일) |

### B. 드래곤 알 통치 — "서버에 하나뿐인 알, 모두가 누가 가졌는지 안다" ★ 추천

| 왜 러크만 | 알 하나를 두고 **게임 · 디스코드 · 웹이 같은 이야기**를 함. 웹에서 보고 들어와 뺏으러 갈 수 있음 |
| 손댈 곳 | RucRaid `DragonEggService` (시간 기록) · 홈 광장 기념비 · 칭호 · **웹으로 데이터 보내는 길 (아래 결정 필요)** |

## 웹으로 데이터 보내는 길 (B · E 에 필요)

웹(Vercel)은 지금 게임 DB(집 PC 의 H2 파일)를 읽을 수 없습니다. 상태 페이지는 공개 API(mcstatus.io)를 씁니다.

| 방법 | 장점 | 단점 |
|---|---|---|
| **① 디스코드 채널 경유** (추천) | 새 서비스 없음. 플러그인 → 디스코드(웹훅, 이미 있음) → 웹이 봇 토큰으로 채널 최근 메시지를 읽음 | Vercel 에 봇 토큰을 넣어야 함 · 읽기 속도 제한 (캐시 60초로 충분) |
| ② 외부 저장소 (Upstash Redis 무료 등) | 깔끔 · 빠름 | 새 계정 · 새 비밀 관리 |
| ③ 집 PC 에 작은 API 서버 | 데이터 직접 | 집 IP 노출 · 포트 개방 · 호스팅 옮기면 다시 |

### 소유자가 할 일

1. **피드 채널** — 디스코드에 비공개 채널(예: `#ruc-feed`) + 웹훅 → **약탈** 서버 `plugins/RucCore/config.yml` 의 `relay.feed-webhook-url`
2. **Vercel 환경변수** — `DISCORD_BOT_TOKEN` (MOOKI 봇 토큰, 그 채널을 읽을 권한) · `FEED_CHANNEL_ID` (채널 ID). 없으면 상태 페이지는 설명만
3. **광장 기념비** — **홈** 서버 `plugins/RucCore/config.yml` 에 `egg-reign.monument.enabled: true` 와 world · x · y · z
4. 시즌이 끝나면 통치 1위에게 `/titlegrant <닉> egg_king staff`, 다음 시즌은 `egg-reign.season` 을 바꿈 (약탈 · 홈 둘 다)
5. 게임 안 확인 (위 표) — 숫자(현상금 10% · 최소 2,000 · 수수료 · 추천 점수)는 전부 config 에서 조정

## E. 러크 연대기 (2026-10-09)

**구현 · 4개 서버 jar 배포 (옛 jar `*.bak-20261009-3`).** 웹 `/chronicle` (상태 페이지 현상금 칸 · 검색에서 연결).

| 사건 | 어디 | 조건 |
|---|---|---|
| 🥚 알 주인 교체 | RucRaid `DragonEggService.reignTick` | 다른 사람이 차지할 때 |
| 🎯 큰 현상금 처치 | RucRaid `BountyService.onDeath` | 받은 현상금 ≥ `bounty.chronicle-min` (10,000) |
| 🏰 길드 창설 | RucCore `GuildService.create` | 항상 |
| ⭐ 레벨 이정표 | RucCore `XpService` (award · catchUp) | `chronicle.level-milestones` (50 · 100) 을 처음 넘을 때, "서버 N번째" |

- **피드 채널 하나로 합침 (2026-10-09, 소유자 결정).** 약탈 서버의 상태(`RUCFEED <json>`)는 새로 올리지 않고 메시지 하나를 고쳐 씁니다
