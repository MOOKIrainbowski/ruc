# 맵 디자인 원칙 — `mapfile/` 분석 결과

> 2026-09-13 · 대상: Red City(1.14.4), SkyIsle(1.15.2), render(2)·넓은 평야·북방의 수용소(1.12.2)

분석 방법: 리전 파일(`.mca`)을 직접 파싱해 탑다운 렌더링 + 블록 팔레트 통계를 뽑았습니다.
도구는 `scratchpad/{nbt,render,crop,analyze}.js` 에 있습니다.

---

## 1. 팔레트 — Red City 도심 실측

지하 암반을 제외한 **건축 재료** 비중입니다.

| 재료 | 비중 | 역할 |
|---|---|---|
| polished_granite | 3.75% | **주 재료** (붉은 기 — 도시 이름의 근거) |
| andesite | 3.34% | 보조 회색 |
| granite | 3.22% | 주 재료 거친 버전 |
| diorite | 3.04% | 밝은 대비 |
| oak_planks / oak_log | 0.48% | 목재 포인트 |
| pink / white / black / yellow terracotta | 0.52% | **강조색 4종** |
| bricks | 0.20% | 포인트 |
| 계단·슬랩·벽·랜턴·유리판·발판 | 소량 다수 | 디테일 |

### 배운 것

**재료는 적게, 변형은 많이.** 베이스는 화강암 계열 하나로 통일하고 거친/광택/계단/슬랩 변형으로 질감을 만듭니다. 강조색은 테라코타 4종뿐이며 전체의 0.5% 미만 — **강조는 희소해야 강조입니다.**

제 기존 광장은 smooth_quartz + polished_diorite + polished_andesite + chiseled_stone_bricks + prismarine + 콘크리트 3색을 한 화면에 깔았습니다. 베이스가 여러 개라 중심이 없고, 강조색이 흔해서 강조가 되지 않았습니다.

## 2. 형태 — 렌더에서 읽은 것

### 2-1. 폐쇄감(enclosure)이 공간을 만든다

Red City의 광장들은 **건물 덩어리에 둘러싸여** 있습니다. 길은 좁고(2~4블록) 건물은 붙어 있어서, 빈 공간이 "남은 자리"가 아니라 **의도된 방**처럼 읽힙니다.

제 기존 광장은 사방이 뚫린 원반 위에 분수 하나였습니다. 벽이 없으니 공간이 아니라 바닥이었습니다.

### 2-2. 완벽한 원·사각형은 인공적으로 보인다

건물 외곽선이 전부 불규칙 다각형입니다. 도로도 곡선으로 갈라집니다. 반면 제 광장은 정원(正圓) + 정삼각 배치라 기계적으로 보였습니다.

### 2-3. 분기점에는 랜드마크

원형 탑(황갈색 지붕)이 교차로마다 반복 등장해 시각적 리듬과 길찾기 기준을 만듭니다. 아치형 관문도 진입부를 명확히 합니다.

**허브에 적용하면: 서버 선택 지점이 곧 분기점이므로, 3x3 단상이 아니라 관문 건축이어야 합니다.**

### 2-4. 높이차

지붕 높이가 제각각이라 음영이 살아 있습니다. 제 광장은 y=64 단일 평면 + 기둥 하나였습니다.

### 2-5. 자연물 삽입

건물 사이사이 작은 녹지, 선형 가로수, 수변(운하·연못)이 섞여 있습니다. 돌만 깔린 면이 없습니다.

## 3. 새 허브 설계 지침

| 원칙 | 적용 |
|---|---|
| 베이스 1계열 + 변형 | 안산암/화강암 계열로 통일, 계단·슬랩·벽으로 질감 |
| 강조색은 희소하게 | 브랜드 그린은 배너·양탄자·잎 등 1% 미만으로만 |
| 폐쇄감 | 광장 둘레에 아케이드 파사드 링 (높이 6~9) |
| 랜드마크 | 중앙 기념탑 + 서버별 관문 아치 3기 |
| 높이차 | 광장 1단 낮춤, 계단 진입, 지붕 높이 3단계 |
| 자연물 | 화단·나무·물길 삽입 |
| 불규칙성 | 원형 외곽에 요철, 파사드에 돌출부 |

## 4. 분석 도구의 한계 (정직하게)

- **1.12 이하 맵 3개는 색 재현이 부정확합니다.** 구형 숫자 ID + Data 니블 변형 테이블이 없어 상당수가 회색/기본색으로 렌더됩니다. 구조 윤곽은 보이지만 재료는 못 읽었습니다.
- **SkyIsle은 리전 데이터가 비어 있습니다** (압축 파일 15KB).
- 탑다운 렌더는 **지붕만** 보여줍니다. 실내·입면·아치 단면 같은 건 안 보입니다.

### 추가로 주시면 도움이 되는 것

1. **참고하고 싶은 허브/스폰 맵** — 도시 맵보다 스폰 허브 맵이 직접적입니다
2. **1.13 이상 버전 맵** — 블록 이름이 그대로 읽혀 팔레트 분석이 정확합니다
3. **원하는 분위기의 스크린샷** — 탑다운으로는 입면(벽면 디테일)을 못 읽습니다. 게임 내 스크린샷 몇 장이면 훨씬 정확해집니다
4. `.schem` / `.nbt` 구조물 파일이 있다면 그것도 직접 파싱 가능합니다

## 5. 2차 개선 (피드백 반영, 2026-09-13)

받은 지적 4가지와 대응입니다.

### 5-1. 블록 종류가 빈약하고 색 그라데이션이 없다

**그라데이션 램프 + 디더링**을 도입했습니다 (`Palette.java`).

두 재료를 딱 잘라 붙이면 경계선이 보입니다. 좌표 해시 노이즈로 전환 구간을 흩뿌리면 자연스럽게 섞입니다. 손으로 지은 맵이 좋아 보이는 이유의 상당 부분이 이 "섞임"에 있습니다.

```
STONE_RAMP   심층암타일 → 조약돌심층암 → 응회암벽돌 → 안산암 → 돌 → 섬록암 → 방해석 → 석영  (13단계)
WARM_RAMP    다진진흙 → 진흙벽돌 → 벽돌 → 화강암 → 테라코타 계열  (9단계)
COPPER_RAMP  구리 → 노출 → 풍화 → 산화  (지붕. 산화 청록이 브랜드 그린과 이어짐)
```

**측정 결과 (표면에 실제로 보이는 면 기준, 19,322칸)**

| 항목 | 이전 | 현재 |
|---|---|---|
| 블록 종류 | 약 12종 | **49종** |
| 최다 블록 비중 | 30% 이상 | **16.3%** (단색 면 없음) |
| 디테일 블록(계단·슬랩·벽·창살·체인·조명) | 1% 미만 | **8.0%** |

### 5-2. 경계 밖으로 떨어지면 허공에서 못 돌아온다

`VoidGuard` 추가. 허브 월드에서 Y < 44 이면 스폰으로 복귀시킵니다.

낙하 데미지를 꺼둔 탓에 죽지도 않아서 재접속 외에는 방법이 없었습니다.
`PlayerMoveEvent` 대신 5틱 주기 검사를 쓰는 이유는, 필요한 정보가 "떨어지는 중인가" 하나뿐이라 이동 이벤트를 매번 받을 이유가 없기 때문입니다.

### 5-3. 구멍이 많아 쉽게 빠진다

**원인**: 보도(r25)와 파사드(r27) 사이 2칸이 아예 안 채워져 있었고, 보도 가장자리에는 제가 `random.nextInt(5)==0 → continue` 로 **일부러 구멍을 뚫고** 있었습니다. 파사드도 각도 순회라 반경이 커질수록 칸이 비었습니다.

**해결**: 순서를 뒤집어 **전체를 덮는 solid 기반판을 먼저 깔고** 그 위에만 짓습니다. 이제 위에 무엇을 짓든 아래는 항상 막혀 있습니다. 파사드는 각도 순회 대신 x,z 래스터 방식으로 바꿔 빈틈이 없습니다.

**검증**: `scratchpad/holecheck.js` 로 반경 76 안의 18,146개 기둥을 전수 검사 → **구멍 0개**.

### 5-4. 규모가 작고 디테일이 부족하다

| 항목 | 이전 | 현재 |
|---|---|---|
| 광장 반경 | 19 | 26 |
| 파사드 | 27~32 (5두께) | 36~44 (8두께) |
| 전체 지반 | 없음 | 반경 80 |
| 파사드 높이 | 7/9/11 | 10/13/16 |
| 기념탑 높이 | 14 | 23 |

바깥 반경 56~80 은 자연 지형(기복 + 풀·이끼·자갈·포졸 혼합 + 나무 약 100그루)으로 채웠습니다. 회색 통판이 드러나면 "잘라낸 판때기"로 보이고, 체감 규모도 줄어듭니다.

### 남은 한계

- **입면(벽면) 디테일은 여전히 추정입니다.** 탑다운 렌더는 지붕만 보여줍니다. 게임 내 스크린샷을 주시면 훨씬 정확해집니다.
- 절차적 생성은 숙련된 빌더의 수작업을 대체하지 못합니다. 반복 가능하고 수정이 빠른 것이 장점이고, 유기적인 불규칙함은 약점입니다.

## 6. 3차 — 정원 로비로 전환 (2026-09-13)

### 6-1. 참고 자료에 대한 정직한 보고

**영상 4편은 보지 못했습니다.** 저는 동영상을 재생할 수 없습니다. 제목만 확인했습니다.

| 링크 | 제목 |
|---|---|
| cOEfcGJeCm8 | How to build a Beautiful Gazebo (예쁜 쉼터) |
| IpyGbI0VE-c | How to build a Realistic Working Fountain (작동하는 분수대) |
| Hh98_zB_QDk | How to build the Perfect Farmer House (농부의 집) |
| al-XKTgJcBs | How to build an Wooden Survival House (단층 목조주택) |

즉 **"무엇을 지을지"는 제목에서 얻었지만, "어떻게 지었는지"는 못 봤습니다.**
아래 구조물은 제목이 가리키는 대상을 꿀렘 로비 팔레트 분석 + 일반적인 건축 관례로 제가 설계한 것입니다.

### 6-2. `꿀렘 로비` 분석 (1.10.2)

이건 제대로 파싱했습니다. 표면 29,635칸 실측:

| 재료 | 비중 |
|---|---|
| water | **22.4%** |
| grass_block | 19.0% |
| pink_wool + white_wool + white_stained_glass | **26.5%** |
| tall_grass | 9.9% |
| stone_bricks + stone_slab | 13.7% |
| quartz | 3.8% |
| 꽃 (dandelion/sunflower/poppy) | 2.5% |

**결정적 발견: 이건 석재 광장이 아니라 정원 섬입니다.**
물과 식생이 표면의 70%를 차지하고, 석재는 길과 중앙 단상에만 씁니다.
분홍·흰 덩어리는 벚꽃 캐노피인데, 1.10에는 벚나무가 없어서 **분홍양털 + 흰색 유리로 흉내**낸 것입니다. 1.21에는 실제 벚꽃 블록이 있으므로 그쪽을 씁니다.

제가 2차까지 지은 것은 석재 광장 + 구리 지붕 파사드였습니다. **방향 자체가 달랐습니다.**

### 6-3. 전환 결과

| 구성 비율 | 꿀렘 로비 | 2차(석재 광장) | 3차(정원) |
|---|---|---|---|
| 물 | 22.4% | 4.2% | **12.2%** |
| 수목(잎/줄기) | 26.5% | 15.2% | **22.3%** |
| 석재 | 15.0% | 29.7% | **22.8%** |
| 초화 | 11.5% | 8.5% | 7.3% |

물은 아직 목표에 못 미칩니다. 허브는 통행이 필요해 물을 무한정 늘릴 수 없는 제약이 있습니다.

### 6-4. 추가한 구조물 (`Structures.java`)

- **작동하는 분수** — 3단 구조. 상단 관 → 중단 수반 → 하단 수조로 물이 실제로 흘러내립니다
- **팔각 정자(쉼터)** — 벚나무 기둥 8개 + 원뿔 지붕 4단, 가운데 모닥불과 앉는 계단
- **농부의 집** — 가문비+테라코타 벽, 박공 지붕, 밖에 밀밭과 물길, 건초더미
- **목조주택** — 참나무+자작나무 벽, 현관 차양, 내부에 책장·베틀
- **벚나무** — 실제 `CHERRY_LEAVES` + 바닥에 `PINK_PETALS`(떨어진 꽃잎)

레이아웃도 참고 맵을 따라 **십자(4축) 동선**으로 바꿨습니다. 3축은 서버 관문, 북쪽 축 끝은 쉼터입니다.

### 6-5. 여전히 남은 한계

- 영상의 건축 기법은 반영하지 못했습니다. **게임 내 스크린샷이나 схем 파일**이 있으면 훨씬 정확해집니다.
- 물 비중이 목표보다 낮습니다.
